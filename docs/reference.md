# Справочник ArrowsHDL 0.1.0

**Экспериментальная версия.** Компилятор преобразует поддерживаемый синтезируемый
Verilog/SystemVerilog в физическую карту Logic Arrows. Все команды доступны также
через `python -m arrowshdl`. Результаты записываются непосредственно в `--out`.

## CLI

| Команда | Назначение |
|---|---|
| `compile a.v b.v --top top -o build` | Полная компиляция без TOML |
| `compile -c a.v --top part -o part.object.json` | Раздельная компиляция |
| `link part.object.json top.object.json --top top -o build` | Связывание и размещение |
| `build project.toml -o build` | HDL, размещение, компоненты и виджеты |
| `test map.save.txt scenario.json -o report.json` | Симуляция с проверкой ожиданий |
| `simulate map.save.txt scenario.json -o trace.json` | Тот же движок; наблюдения допустимы без ожиданий |
| `test --suite tests -o report.json` | Регрессии из исходного репозитория |
| `check` | Проверка установленного HDL-фронтенда и физического симулятора |
| `decode map.save.txt -o map.json` | Декодирование клеток |
| `encode map.json -o map.save.txt` | Игровое сохранение v0 |
| `graph map.save.txt -o graph.json` | Физический граф зависимостей |
| `preview map.save.txt -o preview.png` | Предпросмотр из модели клеток |

`compile`: `--std 1364-2005` или `1800-2023` (по умолчанию), `-I DIR`,
`-D NAME=VALUE`, `-G PARAM=VALUE`, `-L library.v`, `--timeout SECONDS`,
`--max-cells N`, `--layout compact|sparse|fixed|macro-grid`, `--preview`.
`--extern MODULE` объявляет внешний модуль только при `-c`; его реальное
определение и интерфейс проверяются при связывании. Для раздельной компиляции
параметризованных внешних модулей передавайте совместимые объявления портов.

`build`: `--layout compact|sparse|macro-grid`, `--timeout`, `--max-cells`, `--test`.
Последний параметр формирует тестовую копию с источниками и приёмниками;
дисплеи сохраняются. Для закреплённой карты требуется корректный интерфейс
fixture в bindings. `test`/`simulate`: `--manifest build.json`, `--vectors`,
`--timeout`, `--no-optimize-cycles`. С `--vectors` входной JSON — список
`{"inputs":{"a":0},"expect":{"y":1}}`; manifest обязателен.

Код завершения: **0** — успех, **1** — неверный результат теста,
**2** — ошибка входных данных или выполнения. Общий таймаут включает
фронтенд, оптимизацию, размещение и запись файлов; процесс и его дочерние
процессы завершаются при превышении бюджета. Файлы, успевшие записаться
до ошибки, не считаются успешной сборкой.

## Python API

```python
from arrowshdl import compile, build, compile_object, link, simulate

result = compile(["top.sv", "part.v"], top="top", out="build", timeout=600)
result = build("project.toml", out="build")
obj = compile_object("part.v", top="part", out="part.object.json")
result = link(["part.object.json", "top.object.json"], top="top", out="build")
report = simulate("build/top.save.txt", "scenario.json")
```

`BuildResult.cells`: словарь `(x,y) → Cell(type,rotation,mirrored)`;
`ports`: таблицы inputs/outputs; `metadata`: описание сборки;
`artifacts`: имена суффиксов (`save.txt`, `build.json` и другие) → абсолютные
`Path`. `compile_object` возвращает документ объекта и может не записывать файл.
`simulate` принимает клетки, путь карты или BuildResult и сценарий либо путь JSON.
Для логических векторов нужны функции `arrowshdl.test_harness.add_fixture`
и `make_scenario`: публичный `simulate` сам не создаёт тестовые контакты.
Ошибки входа представлены `MapError`; ошибки внешних процессов сохраняют
диагностику. `encode`/`decode` доступны из `arrowshdl`.

## Поддерживаемый HDL

Фронтенд — Yosys. Поддерживаются комбинационные выражения, операторы
арифметики и сравнения, условные выражения, статические циклы и generate,
иерархия, параметры, шины, `always @*` и `always_comb`. Выбранный номер
стандарта определяет режим чтения, **не обещает поддержку всего стандарта**.
VHDL, классы, динамические структуры и произвольная поведенческая
последовательная логика не реализованы. `always @(posedge clk)`, latch,
память HDL и неподдерживаемые ячейки дают явную ошибку.

Проверяются наличие модулей, направления и ширины подключений, конфликт
драйверов и неопределённые сети. Компилятор оптимизирует булев граф,
сопоставляет нативные макросы, размещает и разводит стрелки, проверяет
физические контакты. Для сложного графа автоматическая разводка может
не найти решение в бюджете; увеличьте таймаут или задайте размещение.

## Нативная библиотека

Библиотека `arrowshdl/library/arrows.v` подключается автоматически.
Модули используют стандартный синтаксис Verilog.

| Модуль | Поведение |
|---|---|
| `arrows_set(input [1:0] I, output O)` | Нативная SET: два активных входа устанавливают, один сбрасывает, отсутствие сохраняет состояние |
| `arrows_toggle(input I, output O)` | Переключение на **каждом активном игровом такте** |
| `arrows_random(input I, output O)` | Нативная случайность; экземпляры независимы |
| `arrows_delay(input I, output O)` | Нативная стрелка задержки type 4 |
| `arrows_detector(input I, output O)` | Детерминированный макрос детектора сигнала |
| `arrows_edge(input I, output O)` | Импульсы при обоих изменениях уровня |
| `arrows_rise(input I, output O)` | Импульс при появлении уровня |
| `arrows_timer #(TICKS=1)(input I, output O)` | Цепочка из TICKS стрелок, 1…1024; задерживает передачу, не считает события |
| `arrows_impulse(output O)` | Однократный стартовый импульс type 9 после сброса карты |
| `arrows_button(input I, output O)` | Направленная кнопка type 24 |
| `arrows_indicator(input I, output O)` | Обычная стрелка для индикации |

Нативные элементы читают состояние предыдущего такта. Разводка добавляет
задержку до и после макроса; автоматическая карта не является синхронным
HDL-симулятором. SET, TOGGLE, RANDOM, память и импульсы сохраняются при
оптимизации, одинаковые экземпляры RANDOM не объединяются. Автоматические
макросы принимают не более трёх физических входов; для более сложных
структур используйте закреплённый шаблон.

Низкоуровневый `arrows_logic #(OP)` выражает нативную операцию с I[10:0],
B[10:0] и S. `arrows_cell` с TYPE/X/Y — совместимый низкоуровневый вход,
но примеры релиза используют **логику HDL и отдельную геометрию**.
Правила контактов и семантика типов: [native-rules.md](native-rules.md).

## TOML v1

TOML необязателен. Пути sources, libraries, include_dirs, bindings, template,
компонентов и шрифтов разрешаются относительно соответствующего TOML.
Неизвестные поля и версии отклоняются.

```toml
version = 1
sources = ["top.sv", "part.v"]
top = "top"
# inputs = []  # отключить автоматические кнопки
# outputs = [] # отключить автоматические индикаторы

[language]
standard = "1800-2023"

[[inputs]]
name = "request"
to = "a"             # можно a[0]
widget = "button"
size = [3, 3]

[[outputs]]
name = "answer"
from = "y"
widget = "indicator"
```

Если inputs/outputs отсутствуют, добавляются виджеты по умолчанию; пустой
список отключает их. `parameters`, `defines`, `include_dirs`, `libraries`
управляют чтением HDL. Политика компилятора выбирается CLI; поля layout.mode нет.

`placement.input_buses` и `input_bus_gap` задают размещение входных шин.
`[[placement.grids]]`: instances (шаблон имени), step, origin, max_cell_size.
`[[placement.placements]]`: instance, at. `placement.template` ссылается
на физический TOML v1: `[[modules]] hdl,geometry,source` и
`[[instances]] path,at`; interfaces описывает внешние контакты.
Геометрический JSON v1 содержит cells (имя экземпляра → at,type,rotation,mirrored)
и presentation; физический тип сверяется с операцией HDL. Связи остаются в HDL.
Контакты шаблона сверяются с HDL после развёртывания и соединений.
`bindings` описывает порты и наблюдения и не подменяет вычисление картой.

`[[timing]]`: name, from, to, max_ticks и необязательные states (координаты
границ памяти). Концы — координаты либо имена логических портов.
Контракт проверяет физический путь в окончательной карте после подключения
виджетов. Имена портов разрешаются в contact, а не во внешнюю площадку fixture;
циклические зависимости требуют явно обозначенных границ памяти.
Это проверка бюджета распространения, а не доказательство протокола игры.

`[[modules]] name,hdl,parameters,at` размещает скомпилированные HDL-блоки.
`[[components]] name,file,at,rotation` подключает готовую карту.
`[[connections]] from,to` соединяет `экземпляр.порта` одинаковой ширины.
Карта компонента рассматривается как **непрозрачный блок**: допустимы
перенос и поворот; внутренние клетки и пустоты сохраняются.

Описание готового блока — отдельный TOML v1 с `map`, `settle_ticks`,
`[ports.inputs]`/`[ports.outputs]`: имя → список записей index,contact,fixture,rotation.
contact должен существовать, fixture быть свободным. `[interface]`
содержит описательные kind,encoding,protocol,bit_order. Интерфейс клавиатуры
может указать CP1251; это не означает автоматическую реализацию протокола.

`[[labels]] name,io,text,font,size,offset` привязывает надпись к I/O;
вместо offset можно указать at. size — положительный целый масштаб.
Шрифт JSON v1: name,height,spacing,space,glyphs (символ → строки из `.` и `#`),
source. Подписи создают пассивные клетки type 25; данные шрифта внешние.

## Форматы и симулятор

Версии независимы: пакет **0.1.0**, TOML **1**, object **1**, игровые
сохранения **v0**. Object JSON содержит format/version/compiler/standard/top,
interface, parameters, instances, timing и исходное RTLIL-представление.
При связывании проверяются версии, стандарт, конфликты модулей и интерфейсы.
Поле timing объектов пока пустое: контракт задаётся схемой TOML.

Финальный комплект: `.save.txt` (Base64), `.map.json` (клетки),
`.build.json` (порты, размеры, хеши, задержки и выбранная стратегия),
`.logic.json` (граф, когда доступен), `.bindings.json` (наблюдения шаблона).
`.report.json` создаётся проверкой. `map_hash` — хеш канонической модели;
`save_sha256` — **SHA-256 точных байтов файла**, включая завершающий перевод строки.

Физический симулятор использует vendored GraphDLC, фиксированный seed и
опциональное ускорение циклов. Сценарий JSON:

```json
{"ticks":20,"frame_ticks":[10,10],"seed":123456789,
 "inputs":[{"at":[0,0],"values":[0,1]}],
 "expect":[{"at":[4,0],"values":[0,1]}],
 "observe":[[2,0]]}
```

inputs управляет тестовыми Source type 22, expect проверяет Target type 23.
values содержит по значению на отсчёт frame_ticks; observe читает состояние
без изменений схемы. Дополнения Python-обёртки: controls заменяет указанные
направленные кнопки type 24 источниками в тестовой копии; probes добавляет
Target только в свободные координаты; assert проверяет существующие клетки
значениями 0/1/null. null пропускает отсчёт. Исходная карта остаётся неизменной;
`simulated_map_hash` относится к тестовой копии. Лимиты nodes/ticks задаются
через API `limits`. Отчёт сохраняет проверки, ошибки, наблюдения и параметры
движка. CLI добавляет хеши исходного сохранения и сценария.

Отсутствие ожиданий означает только успешное выполнение симуляции.
Функциональная корректность требует независимого оракула: такие проверки
для примеров и сапёра находятся в `tests/projects`, а не в компиляторе.
