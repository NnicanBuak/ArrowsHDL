# Compact manual mux8

Ручная карта пользователя от 7 октября 2026 года, сохранённая
[в исходном Base64](mux8.manual.original.save.txt).
Она реализует `y = data[sel]` и прошла **4096 проверок**: все 2048 сочетаний
в прямом и обратном порядке, без сброса между векторами.

| Показатель | Ручная карта | Компилятор |
|---|---:|---:|
| Клетки без Source/Target | 68 | 64 |
| Поле без Source/Target | 9×12 | 10×11 |
| Поле с Source/Target | 11×13 | 11×12 |
| Стрелки ядра | 40 | 39 |
| Поле ядра | 8×11 | 9×11 |
| Глубина ядра | 11 | 11 |
| Время удержания для проверок | 19 | 22 |

Для проверки биты data назначены контактам `(0,1)`, `(0,2)`, `(0,4)`,
`(0,5)`, `(0,7)`, `(0,8)`, `(0,10)`, `(0,11)` по порядку.
Биты sel назначены `(1,0)`, `(4,0)`, `(7,0)`; выход — `(8,7)`.
Это назначение восстановлено по геометрии и подтверждено полным перебором.
Все тестовые Source/Target располагаются снаружи; проверка внешних границ проходит.

## Изменения общего поиска после сравнения

Теперь автоматическая шина допускает неодинаковый шаг между битами; data
компилятора также имеет расстояния **1, 2, 1, 2, 1, 2, 1**. Общий упаковщик
собирает связанные ветви рядом, допускает прямые связи и прыжки через клетки
без соединения с ними. OR может объединять сигналы и одновременно быть прыжком
или разветвлением. NOT сравниваются в общем и локальном вариантах.

Положения отдельных групп операций и модулей меняются по результатам реальной
трассировки. Входные контакты подбираются после размещения логики, а выход —
после соединения ядра, на любой из четырёх внешних сторон.

Компилятор уже использует меньше клеток и меньшее полное поле, но **ручное ядро
остаётся уже на одну колонку**, а время удержания меньше. Геометрия не копируется
из ручного сохранения; общий поиск не гарантирует глобальный минимум.

## Последовательные сигналы и переключение выбора

Тест с удержанием входов 19 тактов подтверждает установившийся результат.
Он не проверяет отсутствие промежуточных импульсов.

При **фиксированном sel** проверены 240 последовательных значений каждого
канала, подаваемых **каждый такт**, с одновременным изменением остальных данных.
Поток сохраняется; задержки для каналов 0–7: **12, 11, 10, 11, 12, 11, 10, 11**
тактов от задания Source до чтения Target в конце такта.
Таким образом, задержка одного бита и интервал между битами различаются.

При смене sel обнаружены положительные ложные импульсы в **32 из 336**
проверенных переходов между каналами, оба конечных значения которых равны нулю.
Например, при `data=1` переход `sel=2 → sel=1` выдаёт `y=1` на тактах
**11–13 после изменения**, хотя data[2] и data[1] равны нулю.
Причина — разные задержки ветвей данных, выбора и NOT.

Проверка случайного изменения data и sel каждый такт не нашла единой
задержки 1–25 тактов, которая превращала бы выход в точный поток `data[sel]`.
Для такого режима потребуется согласование задержек и отдельный протокол
считывания установившегося результата либо синхронные ступени хранения.

```powershell
ArrowsHDL/.venv/Scripts/python.exe ArrowsHDL/examples/hdl/multiplexer/manual_mux8/timing.py
```

[Измеренные задержки и примеры импульсов](mux8.manual.timing.json).
