# Компактный 8-битный сумматор

**Входы:** `a[7:0]`, `b[7:0]`, `cin`. **Выходы:** `sum[7:0]`, `cout`.
Вычисляет `a + b + cin`; младшие восемь бит — `sum`, девятый бит — `cout`.
[Исходник Verilog](adder8.v) собирает восемь разрядов с теми же уравнениями,
что [учебный полный сумматор](../full_adder/README.md) из
[Nandland](https://nandland.com/full-adder/). Восьмиразрядный модуль и тесты
написаны в этом проекте; это расширение примера, а не копия готового урока.

## Критерии и результат

[**Изображения схем по итерациям и краткая история компилятора**](history/README.md).

- Исходник и сохранённый граф Yosys остаются неизменными; технологические преобразования сохраняют вычисляемую функцию.
- Контакты каждого векторного порта упорядочены, расположены рядом и не перемещаются по одному.
- Минимизируется физический предел установления при ограничении площади и числа стрелок.
- Все комбинации входов сверяются с независимым целочисленным сложением.
- Проверяются переключения, цепочки переноса и возврат сигналов в ноль.
- JSON/Base64 после повторного чтения дают те же клетки, что исполняет тест.
- Source/Target добавляет отдельный `testbench.py` к копии обычной карты.

**Все критерии выполнены.** Тот же исходник и граф Yosys с 49 узлами:

| Показатель | Старые шины | Предыдущая компактная сборка | Новая сборка |
|---|---:|---:|---:|
| Стрелок в обычной карте | 30 393 | 623 | **58** |
| Размер поля | 793×269 | 36×34 | **18×4** |
| Площадь поля, клеток | 213 317 | 1 224 | **72** |
| Предел установления, тактов | 3 778 | 93 | **20** |

Относительно предыдущей компактной сборки стрелок меньше на **90,69%**,
площадь уменьшилась на **94,12%**, предел установления — на **78,49%**.
Предыдущая сборка в таблице — историческое измерение; старый режим `sparse`
и новая сборка воспроизводятся текущей тестовой программой.
Тестовая карта содержит **84 клетки**: 58 обычных + 17 Source + 9 Target;
её поле — **20×6**, с учётом выступающих тестовых портов.
Хеш одного и того же графа записан в описаниях обеих сборок и
[отчёте сравнения](build/adder8.comparison.json).

Оптимизация включена по умолчанию. [Технологическое отображение](../../../src/technology_mapping.py)
распознаёт по связям пять булевых элементов одного разряда полного сумматора
и заменяет их двумя игровыми элементами: **XOR трёх входов** и **порог ≥2**.
Второй вычисляет перенос: из трёх битов должны быть включены хотя бы два.
Исходный `.logic.json` не изменяется; производный граф содержит **25 узлов**:
16 логических элементов и 9 выходных буферов. Все восемь преобразований
записаны в `build.json/technology_mapping`. Наблюдаемые промежуточные сигналы
не удаляются.

[Размещение по разрядам](../../../src/native_adder_layout.py) узнаёт полную
цепочку переносов произвольной ширины, без зависимости от имени модуля или портов.
Разряды идут слева направо; A — ровной шиной сверху, B и Sum — снизу с шагом
**2 клетки**, Cin — слева, Cout — справа. Сигналы входят непосредственно в
свой разряд, перенос проходит к соседнему; длинных обратных трасс нет.

Если граф не соответствует этому шаблону, [общий маршрутизатор](../../../src/compact_layout.py)
размещает внутренние элементы и прокладывает A*-трассы с разветвлениями и прыжками.
Порты фиксированы для всех кандидатов. Внутренние связи строятся первыми и
защищаются; затем подключаются внешние провода. Из вариантов выбирается меньшее
число стрелок ядра, затем меньшая задержка, при ограничении площади.
Глобальный минимум для произвольного графа не гарантируется.

Для сравнения [арифметическое ядро пользовательского снимка](../../reference_adder8/README.md)
занимает **56 стрелок / 16×4 / 20 тактов** и складывает A+B с нулевым начальным
переносом. Наши две дополнительные клетки — контакт Cin и отдельный терминал Cout.
Полная карта снимка имеет 411 стрелок, включая память и последовательную передачу;
её размер сравнивается отдельно.

**Без трасс ввода/вывода оба ядра совпадают по размерам:** 16 логических
элементов и 7 стрелок переноса — **23 стрелки, 15×2 клетки, 15 тактов**.
Это метрики `build.json/logic_core`. Полные 20 тактов учитывают входные
контакты, выходные буферы и Source/Target и используются для проверки результата.

## Проверки

**Полный перебор:** 256 × 256 × 2 = **131 072 вектора**, **1 179 648 проверок
выходных битов**, **2 621 440 тактов**, ошибок **0**. 32 пакета по 4 096 векторов
запускают настоящую физическую карту в GraphDLC; каждый такт исполняется ядром.
Состояние сохраняется между векторами внутри пакета и сбрасывается перед
следующим пакетом. Ожидания вычисляет Python: `sum=(a+b+cin)&255`,
`cout=(a+b+cin)>>8`, независимо от синтезированной логики.

Дополнительно **2 312 векторов переключений / 20 808 проверок битов / 46 240 тактов**:
цепочки переноса длины 1–8, изменение отдельных входных битов, граничные случаи,
воспроизводимые случайные значения и их инверсии. Прежняя большая карта тоже
проверена физической симуляцией на восьми граничных примерах. Все проверки прошли.

Примеры измерений:

| a | b | cin | sum | cout |
|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 0 |
| 1 | 1 | 0 | 2 | 0 |
| 127 | 1 | 0 | 128 | 0 |
| 255 | 0 | 1 | 0 | 1 |
| 255 | 255 | 0 | 254 | 1 |
| 255 | 255 | 1 | 255 | 1 |
| 85 | 170 | 0 | 255 | 0 |
| 85 | 170 | 1 | 0 | 1 |

Векторы удерживаются **20 тактов** до проверки. Это консервативная граница
по реально проложенным путям, включая Source/Target; поток новых значений на
каждом такте пока не поддерживается. Профиль GraphDLC — `01232bd`.
Сравнение с текущей браузерной игрой отдельно не выполнено:
`verified_against_current_game: false`.

## Запуск

После установки зависимостей по [README проекта](../../../README.md):

```powershell
python ArrowsHDL/examples/hdl/adder8/testbench.py
```

Команда заново синтезирует исходник, размещает один граф двумя способами,
запускает переключения и полный перебор, сохраняет результаты и изображения.
`--quick` пропускает только полный перебор. Для компиляции своего исходника:

```powershell
python ArrowsHDL/src/verilog_compile.py design.v --top design --out build/design
```

Прежний вариант выбирается параметром `--layout sparse`. Обычный Verilog
`assign {cout,sum}={1'b0,a}+{1'b0,b}+cin;` также поддерживается и проверяется
отдельным регрессионным тестом.
