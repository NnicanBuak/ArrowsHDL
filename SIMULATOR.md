# Logic Arrows CLI

CLI принимает сохранение карты v0 и JSON-сценарий теста, запускает симуляцию без
браузера и визуализации и проверяет выходы по тактам. Используется **настоящее
ядро GraphDLC на Rust**, а не приближённое моделирование булевых выражений.

## Критерии качества

- Сигналы, блокировки, задержки и память обновляются по тактам.
- Source/Target доступны тесту по координатам и не обходятся оптимизатором.
- Ускоренная симуляция совпадает с простой клеточной моделью на эталонных тестах.
- Неизвестные элементы и неправильные сценарии вызывают ошибку, а не успешный тест.
- Для больших схем ограничены время исполнения и бюджет поиска колец.

## Сборка и запуск

Нужны Python 3.10+, Node.js 20+ и Rust/Cargo. На Windows Rust требует штатные
инструменты линковки для выбранного toolchain. Ассемблер использует Python,
граф строится один раз в Node.js, такты исполняются нативным Rust-кодом.

Из корня репозитория:

```powershell
cargo build --release --locked --manifest-path ArrowsHDL/native/Cargo.toml
python ArrowsHDL/src/arrowasm.py assemble ArrowsHDL/examples/identity.l.asm -o ArrowsHDL/examples/identity.save.txt
python ArrowsHDL/src/logicarrows.py --save ArrowsHDL/examples/identity.save.txt --test ArrowsHDL/examples/identity.test.json
```

Вместо `--save` можно передать строку Base64 через `--code` или модель JSON
через `--map`. Общая функция `simulation.simulate(cells, scenario)` принимает
клетки напрямую, без обязательной промежуточной записи сохранения.
`--report report.json` сохраняет отчёт. `--timeout 60` ограничивает время каждой
стадии в секундах; по умолчанию 60. Это отдельные процессы, зависание не оставляет
внутри CLI бесконечный цикл ожидания. Код завершения:

| Код | Значение |
|---|---|
| 0 | Все проверки прошли |
| 1 | На приёмнике получен неверный сигнал |
| 2 | Ошибка карты, сценария, сборки, графа или таймаут |

Собранный `src/compile-graph.mjs` включён в проект: npm для обычного запуска
не требуется. Для изменения TypeScript-адаптера:

```powershell
npm ci --ignore-scripts --prefix ArrowsHDL/tools
npm run build --prefix ArrowsHDL/tools
```

## Сценарий

Специальные клетки игры уже кодируются в сохранении:

| Имя в ассемблере | ID | Назначение |
|---|---|---|
| `level_source` | 22 | Внешний сигнал теста **или** входящий сигнал карты; отправляет вперёд |
| `level_target` | 23 | Принимает сигнал, доступен проверке; не передаёт его дальше |
| `source` | 2 | Обычный постоянный источник в четыре стороны, не управляемый тестовый вход |

`inputs` связывает последовательность с координатами Source, `expect` — с
координатами Target. Последовательности содержат ровно `ticks` значений 0/1.

В `expect.values` также допустим **null**: на этом такте выход измеряется,
но не сравнивается. Каждый выход должен иметь хотя бы одну проверку 0/1;
входы null не принимают. Это позволяет удерживать входной вектор до установления
длинной схемы и проверять результат на последнем такте. `checked_samples`
в отчёте показывает число фактически выполненных сравнений.

Для больших переборов есть компактный сценарий с **`hold_ticks`**. Значения
портов в нём задаются по векторам: массив содержит `ticks / hold_ticks` битов.
Каждый бит входа удерживается указанное число тактов; ядро исполняет **каждый
такт физической схемы**, а выход измеряется и проверяется в конце удержания.
`outputs.values` в отчёте содержит эти конечные измерения, `hold_ticks` задаёт
их интервал. Поле должно быть положительным делителем `ticks`; старые сценарии
без поля по-прежнему измеряют каждый такт.

`observe` — необязательный массив координат существующих клеток, например
`[[0,0],[1,0]]`. Их состояния читаются в те же моменты в `observations`,
без изменения клеток или добавления измерительных проводов. Повторные и
отсутствующие координаты отклоняются. При `expect: []` и непустом `observe`
сценарий только измеряет: `checked_samples` равен нулю и `passed` равен `null`.
Ожидаемые результаты в таком режиме сравнивает вызывающая программа.
Без ожиданий и наблюдений сценарий по-прежнему недопустим.

Для импульсов и последовательных протоколов доступен **`frame_ticks`**:
массив длительностей фаз, например `[1,9,1,88,1,60]`. Его положительные целые
значения должны в сумме давать `ticks`; одновременно указывать `hold_ticks`
нельзя. Массивы `values` содержат по одному значению на фазу. Вход удерживается
всю фазу, выход измеряется в её конце, ядро исполняет каждый физический такт.
`null` маскирует сравнение этой фазы. Длительности возвращаются в отчёте,
а координаты и состояния исходной карты сохраняются.
[Сумматор со снимка](examples/reference_adder8/README.md) использует этот режим
для нажатий кнопок, загрузки регистров и чтения результата за 160 тактов.

**Source/Target относятся к тестовой обвязке.** Логика схемы должна работать
без использования их как внутренних логических элементов. Тестовая сборка
содержит эти клетки для программной подачи и измерения сигналов; обычную карту
можно собрать через `arrowasm.py assemble ... --strip-test-ports`. CLI-тесты
запускаются на тестовой сборке, где нужные порты присутствуют. Входные
последовательности и ожидаемые результаты хранятся отдельно от геометрии карты.

```json
{
  "ticks": 8,
  "inputs": [{"at": [0, 0], "values": [1,0,1,1,0,0,0,0]}],
  "expect": [{"at": [2, 0], "values": [0,0,1,0,1,1,0,0]}]
}
```

Каждый тест начинается с нулевого состояния: память очищена, сигналов нет.
Первое значение входа применяется на **такте 1**, и первый выход считывается
после этого такта. В примере `identity` источник включается на такте 1,
стрелка — на такте 2, приёмник — на такте 3. Отсутствующий в `inputs`
Source получает внешний ноль, но может активироваться сигналом карты.
На каждом приёмнике проверяется наличие сигнала, а не его количество.
Кнопки без ручного ввода не нажаты; входные последовательности разрешены
только для специальных Source.

`seed` задаёт seed генератора случайности GraphDLC, по умолчанию 123456789.
Он обеспечивает повторяемость CLI, **не совпадение случайных результатов с
Math.random браузера**. Неизвестные поля JSON отклоняются.

Отчёт содержит `passed`, фактические последовательности, количество ошибок
и первые 100 несовпадений с тактом, координатами, ожидаемым и фактическим значениями.
`optimized_cycles` показывает количество применённых кольцевых оптимизаций.
Флаг `verified_against_current_game` пока всегда `false`.

## Какие оптимизации включены

Зафиксирована версия [GraphDLC](https://github.com/MerinPrime/GraphDLC/tree/01232bdef7d0d399432ddd1a5a5f57e9fcbd4d1b):

1. Заранее построенный граф связей с учётом направления и отражения.
2. **Пересчёт только изменившихся узлов**, приращения счётчиков сигналов
   и отдельные зависимости детекторов — оригинальное Rust-ядро.
3. **Поиск и проверка колец** оригинальными `CycleSearchTask`/`CycleManager`.
   Допустимые кольца переходят в битовую память с головками чтения, записи,
   очистки и XOR — оригинальная реализация Rust.

`--no-cycles` отключает только кольцевую оптимизацию; событийное ядро остаётся.
Тестовые программы компилятора отключают поиск колец: перед запуском карта
проверена как ациклическая, и кольцевое ускорение ей не требуется. Полный перебор
8-битного сумматора выполняется пакетами до миллиона тактов с сохранением
состояния между векторами пакета и сбросом между пакетами.
CLI консервативно запрещает включение Source/Target в тело кольца и использование
этих портов как непосредственных головок записи. Такие карты работают обычным
графом. Это ограничение адаптера ради сохранения внешнего управления тестом.
Для записи в оптимизированное кольцо используется промежуточная обычная стрелка,
как в `examples/ring.l.asm`.

**Ускорение симуляции не уменьшает саму карту.** Сжатие схем компилятором —
отдельный этап. Браузерные функции GraphDLC (UI, темы, перемещение, снимки,
отрисовка и расширение) CLI не использует. Динамическое редактирование во время
теста не поддерживается; граф строится перед запуском.

## Проверки

```powershell
python -m unittest discover -s ArrowsHDL/tests -v
python ArrowsHDL/src/logicarrows.py --save ArrowsHDL/examples/ring.save.txt --test ArrowsHDL/examples/ring.test.json
```

Проверяются базовый ввод/вывод, код завершения при ошибке, задержки, детекторы,
блокеры, память, случайные карты с поворотами и отражениями, повторяемость RNG,
защита входных портов, кольцевые чтение/запись/очистка/XOR. Ускоренный режим
сравнивается с `--no-cycles` и независимой простой моделью по координатам.
Это тесты реализации; они не подменяют сравнение с игрой.

## Ограничения и происхождение

Поддерживаются элементы 1–25 и сохранения v0. Новые/неизвестные типы вызывают
ошибку. Максимум — миллион узлов и миллион тактов; сценарий требует хотя бы
одного приёмника. Поиск колец ограничен 10 миллионами шагов поиска, после
исчерпания нужно запустить с `--no-cycles`.

Семантика сверена с [публичной спецификацией sagdrip](https://github.com/sagdrip/logic-arrows/tree/7d818a68b61f077a611c716af807637aaca8ac84)
(документ описывает игру v1.2) и исходниками GraphDLC. **Полное соответствие
текущей версии игры пока не установлено**: нужны эталонные трассы из игры,
особенно для редких сочетаний памяти, блокировки, задержек и тестовых портов.

Оригинальные файлы GraphDLC сохранены в `vendor/graphdlc` вместе с MIT-лицензией
и commit исходника. Rust-ядро использует глобальное состояние; одна симуляция
работает в одном процессе, параллельные тесты запускаются отдельными процессами.

Публичная ссылка на исходники самой игры из submodule GraphDLC при исследовании
вернула `Repository not found`; наличие исходников текущей игры не предполагается.
